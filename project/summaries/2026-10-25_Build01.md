# 2026-10-25 — swift-cli-kit-auth 0.1 built

Scaffolded from development-guidelines v2.5.0 (the updater's `--to latest` picked
v2.5.0-beta.1, a `sort -V` bug; fixed upstream as development-guidelines PR #2). Built on
SwiftCLIKit 2.3.0 (SSH key input, made for this) and swift-identity 0.7.1.

## Built
- Core types; `PromptedPassword`, `PromptedCode`, `DeviceSignIn`, `Together`; `Admission`;
  `CLISignIn` (me).
- `TerminalPresenter` (agent): line-oriented, `SecureField` for secrets, shown text neutralised
  (Cc/Cf/Zl/Zp → U+FFFD), a revealed secret re-masked before the line ends.
- `AccessLease` (agent): re-resolves a `SessionStore` token; step-up through the same sources.
- `ConnectionPassword` (agent) + `init(authenticator:admission:)` (me).
- 85 tests; gate 0/0, 49 of 49 checkers, no exclusions.

## Open, for the user
- Licence (README says "Not yet chosen"), and creating `jpurnell/swift-cli-kit-auth` (public?).
- A pasted secret keeps a trailing newline (SecureField pastes whole). Strip one, or not?

- No way to cancel a device sign-in while it polls (the presenter has no "watch for Ctrl-C").
